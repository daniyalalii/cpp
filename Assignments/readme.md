## Question 02:
### At a university, the course registration system is built on a fragile network of rules and connections. Every course offered by a department is linked together in a long chain, where each course knows its own details—its code, the number of credit hours, and its position in the department’s course list. But beyond this, each course can also point to other courses: one as a prerequisite that must be completed beforehand, and another as a corequisite that must be taken alongside it. When a student tries to register, the system must carefully follow the chain of prerequisite pointers, ensuring that all required courses have already been taken, while also checking that any corequisite courses are registered together. The danger lies in broken or corrupted data: sometimes, prerequisites form endless loops—for example, if Course A requires Course B and Course B, in turn, requires Course A, the system would be stuck chasing circles forever. To protect students, such cycles must be detected and flagged as errors. If everything is valid, the system then prints the student’s final course plan in the correct order, showing exactly how the student should progress through the program. Duplicate courses must never be added twice, even if they appear multiple times through different prerequisite paths. Beneath the surface, this entire simulation can be crafted in C++ by representing each course as a structure, linking them only through raw pointers, and using careful pointer traversal to build the course plan while managing memory with new and delete.
